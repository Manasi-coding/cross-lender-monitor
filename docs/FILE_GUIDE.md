# File guide

One line per file. Matcher files are frozen (see DECISIONS.md): normalize.py, block.py, match.py and currency.py are in the matcher hash and must not change.

## Plans and records
- SPEC.md: scope, schema, evaluation method, tests (section 13) and schedule. Wins over the plan files.
- CONTRACT.md: the API contract, E1 to E12. The only place endpoint shapes are defined.
- phase_wise.md: the backend build sequence.
- frontend.md: the UI plan, pages and components.
- DECISIONS.md: numbered decisions and results, in order. Sections 17 on were appended during the build; the owner rewrites it.
- AGENTS.md: project working rules.
- README.md: evaluation first, limits, architecture, how to run.
- docs/V2_Addendum_Triage_Evidence_History.md: the v2 change list (exposure, evidence, history), merged into the main docs.
- docs/data_report.md: generated by `python -m pipeline.report` (ingest counts, blocking efficiency, run times, machine).
- docs/run_times.jsonl: one line per block, match or compare run.
- docs/day1_notes.md, day2_notes.md, day4_notes.md: notes from those days.
- docs/blocking_recall_worksheet.md: the 30 holdings for the independent blocking recall check (no counterparts listed).
- docs/history_link_worksheet.md: 30 history links with both quarters side by side.
- docs/blocking_recall_decisions.md: the decision for each of the 30 drawn holdings (first pass, revision, and a follow up on four NONE rows), by an AI assistant.
- docs/history_link_decisions.md: the label and reason for each of the 30 checked history links, by an AI assistant.
- docs/spot_check_sheet.md: 10 displayed rows with filing references and an automated text check; the owner column is for a person.
- docs/diff_reading_order.md: the files changed since commit 73bc5d2 in reading order.
- docs/spec_test_matrix.md and docs/spec_test_matrix.py: SPEC tests 1 to 38 mapped to test names.
- docs/project_closure.md: what is done, what was verified and how, known limits and deployment readiness.
- docs/overnight_log.md and docs/overnight_report.md: the log and final report of the autonomous overnight run.
- docs/FILE_GUIDE.md: this file. docs/demo_script.md: the demo script (recording is out of scope for now).
- docs/screens/: headless Chrome screenshots of each page against the live API.

## Pipeline (`pipeline/`, run as `python -m pipeline.<module>`)
- config.yaml: every tunable. config.py: loads config and env, computes the matcher hash, `--hash`, `--freeze`, `--unfreeze`, `require_frozen_matching`.
- migrate.py: applies `db/migrations` in order, once each.
- ingest.py: rate limited SEC client and the load of each configured filing. adapters.py: per filer adapters that produce raw rows. ixbrl.py: generic Inline XBRL reader. html_schedule.py: reader for the schedule table in the filing HTML.
- normalize.py (frozen): raw rows to normalized holdings. currency.py (frozen): the currency ladder for rows with no unit.
- block.py (frozen): blocking keys and candidate pair generation. match.py (frozen): name scoring and bands.
- compare.py: deterministic full rebuild of borrowers, facilities, comparisons, summary and history in one transaction.
- evidence.py: pure functions for the dossier arithmetic and the seven signal codes.
- link_history.py: within BDC history link, persistence label, hand check worksheet and record.
- sample_labels.py: tuning, held-out and out-of-time draws (the last two refuse unless frozen and the hash matches). tuning_report.py: read only report of the tuning labels.
- evaluate.py: label derived metrics, Wilson and bootstrap, writes metric_results (refuses if the hash changed).
- blocking_recall.py: the independent 30 holding check (draw, record, finalize). report.py: read only data report.
- scout*.py: Day 1 read only scouting of other BDCs and of filing structure. Not part of the pipeline run.
- Dockerfile: the pipeline image.

## Database (`db/migrations/`)
- 001 to 005: raw, staged, curated and evaluation tables, indexes. 006: filing hashes. 007: normalized flags. 008: currency source. 009: exposure_usd. 010: draw records. 011: evidence dossier. 012: history tables.

## API (`api/`)
- src/index.js: starts the server. src/app.js: builds the app and mounts routes. src/errors.js: the error shape and input parsing.
- src/facilities.js: E1 to E5. src/review.js: E6 to E8. src/metrics.js: E9. src/labeling.js: E11 and E12 (flag gated).
- tests/: read.test.js (E1 to E8, E10), metrics.test.js (E9), labeling.test.js (E11, E12), contract.test.js (error matrix), app.test.js (error shape), db.js (scratch databases).
- Dockerfile, package.json, package-lock.json, vitest.config.js: run and test setup (plain Node, no build step).

## Web (`web/`)
- src/main.jsx: routes (`/`, `/borrowers`, `/borrowers/:id`, `/facilities`, `/facilities/:id`, `/review`, `/decisions`, `/metrics`, `/filings`, `/label` outside the shell). src/App.jsx: the shell, sidebar (nav label stays "Triage" for the `/facilities` route), the single global search box (always goes to `/borrowers?search=`), theme toggle, page-transition wrapper, and the window-focus refetch of the shared overview. src/api.js: the fetch wrapper. src/format.js: display rounding and the null wording. src/types.js: JSDoc typedefs of the API shapes, documentation only (CONTRACT.md is the source of truth).
- src/components.jsx: shared cards, tags, tables, inline SVG chart primitives (`DivergenceDonut`, `ClickableDivergenceBar`, `BarList`, `RankedShareList`, `LenderValueBars`, `RangeBar`), the `useFetch` hook (loading/error states plus focus-triggered refetch), and `useCountUp` (animates a stat card to an already-known API value, never a simulated one). `DotPlot`, `HistoryStrip`, `PersistenceTag`, `Banner`, `ExposureTag`, `SignalChip` and `EvidenceTable` are still defined here (E5's dossier and history fields are untouched on the API) but nothing in `web/src` renders them any more.
- src/pages.jsx: Overview (stat-card count-up, clickable divergence bar, a "Data coverage" card), Borrowers (reads `search` only from the URL, filled in by the global header search; no page-local search box), Borrower detail, Filings (adds a client-side lender x quarter coverage matrix and a "Latest filings" list, both built from E10's existing rows). src/triage.jsx: the Facilities page (`TriagePage`, nav label still "Triage") shows all facilities by exposure with clickable status tiles and filter pills (no search box, no sort selector, no URL sync) and `ComparisonPage`, a compact 3-card view (current values, loan details, lender reports) with no sortable table, no evidence-dossier expand and no history strip. src/review.jsx: `ReviewPage` shows one case at a time with Previous/Next paging (not every card listed), fades a card out only after a write succeeds, and records every decision, including a cluster's "Same", to the new session log; `DecisionsPage` (the new `/decisions` page) lists that log. src/metrics.jsx: Metrics now defaults to a compact dashboard with a "Show full statistical detail" toggle; the full breakdown this page always showed (confidence intervals, band tables, out-of-time section, sensitivity) is unchanged, just behind that toggle. src/Label.jsx: the dev only labeling page, unchanged.
- src/decisions.js: the Decisions page's in-memory log of this browser's own review decisions since the last reload (not persisted to disk). No server endpoint lists past decisions; a cluster's "Same" is logged as `ACKNOWLEDGED` with no server call, since the pair is already AUTO or CONFIRMED.
- Dockerfile, nginx.conf, vite.config.js, package.json, package-lock.json, index.html: build and serve.

- test_guards.py: null and zero principal, footnote patterns. test_compare.py: clustering, divergence, exposure, signals. test_history.py: the history link and persistence.
- test_sample_labels.py, test_heldout.py, test_outoftime.py: the draws. test_freeze.py: the freeze and unfreeze. test_evaluate.py: evaluation and metric_results. test_blocking_recall.py: the blocking recall check. test_report_sections.py: report sections. test_migrations.py: the 23 tables. test_api.py: API checks from Python.
- conftest.py: scratch database fixtures and the synthetic row seeder.
