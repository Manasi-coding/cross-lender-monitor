# Spot check sheet for the SEC filings

Ten displayed facility rows to check against the filings by hand. Drawn with seed 1 (Python `random.Random(1)`) from the compared holdings of the 93 facilities (rows with a mark), ordered by facility id then holding id: per BDC, 1 row from a FLAGGED facility and 2 from AGREEMENT facilities (facilities are built only from clean clusters, so none of these comes from a same BDC collision), then 1 more row from the rest. All 3 BDCs are covered, with 3 FLAGGED and 6 AGREEMENT facility rows plus one more.

Values are as served by the API (E5) except fair value, which is in USD from `normalized_holdings` (E5 serves it only as a percent of par), and the printed name and accession, which come from the raw tables. Principal and fair value are in whole USD; filings often print thousands.

**Read this first.** The column `Owner verified in filing (Y/N)` records an independent visual check of the filing by the project owner. For each row, the owner opened the cited SEC filing, located the printed borrower name, and visually checked the relevant filing row against the recorded principal, fair value, maturity and spread. The last two columns are an automated check and are not independent human verification.

For the automated check, the script fetched the filing with the project's EDGAR helper (User-Agent from the environment, 5 requests a second at most), found the table rows that contain the printed name, and looked in one such row for the principal and the fair value (in whole dollars or in thousands), the maturity (in the format that BDC prints) and the spread as served (as `+bps` or as a percent). It also checks that fair value divided by principal equals the served % of par to within 0.01. Y means all of these were found in a single filing table row, so the stored and served values are consistent with the filing text. N means one was not found, and the reason says which. The automated check reads text from the same parsed filing the pipeline used, so it cannot catch a mistake that the filing HTML itself contains, and it cannot show the figure a reader sees on the rendered page.
