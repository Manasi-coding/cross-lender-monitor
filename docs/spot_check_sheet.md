# Spot check sheet for the SEC filings

Ten displayed facility rows to check against the filings by hand. Drawn with seed 1 (Python `random.Random(1)`) from the compared holdings of the 93 facilities (rows with a mark), ordered by facility id then holding id: per BDC, 1 row from a FLAGGED facility and 2 from AGREEMENT facilities (facilities are built only from clean clusters, so none of these comes from a same BDC collision), then 1 more row from the rest. All 3 BDCs are covered, which gave 3 rows from FLAGGED facilities and 7 from AGREEMENT facilities.

Values are as served by the API (E5) except fair value, which is in USD from `normalized_holdings` (E5 serves it only as a percent of par), and the printed name and accession, which come from the raw tables. Principal and fair value are in whole USD; filings often print thousands.

**The last column is a convenience only and is not the verification.** It fetched each filing with the project's EDGAR helper (User-Agent from the environment, 5 requests a second at most), found table rows containing the printed name, and looked in those rows for the principal and the fair value as whole dollars or in thousands. FOUND means a row with the name contained both numbers. NOT FOUND means the name or a number did not appear in that form (a number can be printed in another unit or split across cells). NOT PARSEABLE means the document gave too few table rows. Verify in the filing yourself and fill in Y or N.
